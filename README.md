# 📷 WaveScan — AI 전자레인지 용기 안전 검사 앱

> 카메라로 찍기만 하면, 그 그릇을 전자레인지에 넣어도 되는지 3초 안에 알려주는 앱

## ✨ 주요 기능 & 인터랙션

### 1. AI 카메라 스캔 — 찍자마자 등급이 나온다
스캔 화면 진입 시 `getUserMedia`로 후면 카메라를 즉시 활성화해 실제 화면을 뷰파인더에 띄우고, 화면 중앙 프레임 안에 용기를 맞추도록 스캔 가이드 라인을 애니메이션으로 보여줍니다. 셔터를 누르면 그 순간의 영상 프레임을 캔버스에 캡처해 이미지로 저장하고, "AI 분석 중..." 오버레이가 뜬 뒤 결과 화면으로 자동 전환됩니다. 카메라 대신 앨범에서 사진을 선택해도 동일한 분석 플로우를 타도록 만들어, 매장 진열대 사진이나 이미 찍어둔 사진으로도 바로 검사할 수 있게 했습니다.

### 2. 3단계 안전 등급 + 근거 체크리스트
분석 결과는 단순히 "됨/안됨"이 아니라 **안전 / 주의 / 위험** 3단계 배지로 표시되고, 그 아래에 "BPA Free 인증", "고온 변형 테스트", "금속 장식 유무" 같은 개별 체크 항목이 통과(✅)/경고(⚠️)/실패(🚫) 아이콘과 함께 나열됩니다. 색상만으로 등급을 구분하지 않고 아이콘·문구를 항상 함께 노출해, 어르신이나 색각 이상 사용자도 등급을 오인하지 않도록 설계했습니다. 결과 하단의 "AI 분석 의견"에는 왜 그런 등급이 나왔는지, 어떻게 사용해야 안전한지를 자연어 문장으로 한 번 더 풀어줍니다.

### 3. 로그인 여부에 따라 완전히 달라지는 마이페이지 & 기록
Google 로그인 사용자는 마이페이지에서 프로필, 총 스캔 수·안전 비율·개인 정확도 통계, 기록/설정/탈퇴 메뉴를 모두 이용할 수 있지만, 게스트 상태에서는 같은 화면이 "로그인이 필요해요" 안내와 최소 메뉴(가이드·고객지원)만 보여주는 완전히 다른 뷰로 전환됩니다. 스캔·조회는 비로그인 상태에서도 막지 않되, 기록 저장·통계·프로필 관리처럼 "누적"이 필요한 기능만 로그인 뒤로 제한해, 처음 쓰는 사람도 가입 장벽 없이 핵심 기능부터 체험하게 했습니다.

## 🤖 AI 활용 프로세스

이 프로젝트는 기획부터 퍼블리싱, React 전환까지 단계마다 AI로 1차 초안을 뽑고 실제 사용 맥락에 맞게 검증·수정하는 방식으로 진행했습니다.

**① 기획 단계 — 인터뷰 기반 문제 정의**
1인 가구·자취생 대상 인터뷰 메모를 넘겨 반복되는 pain point를 정리해달라고 요청했습니다.
> "너는 UX 리서처야. 아래 인터뷰 메모 6건을 보고, 사람들이 전자레인지에 그릇을 넣기 전에 어떤 판단을 어떻게 내리는지 공통 패턴 3가지를 뽑아줘. '~용기 재질을 정확히 몰라서 ~하게 된다' 형식으로 정리해줘."

AI가 뽑은 패턴 중 "포장 용기 재질 표기를 아예 안 본다"는 항목은 인터뷰 원문과 맞지 않아 제외했고, 나머지 두 가지("바닥 마크가 잘 안 보인다", "배달 용기는 뚜껑만 보고 판단한다")를 기준으로 카메라 스캔 기능의 우선순위를 정했습니다.

**② 디자인 단계 — 접근성 기준 리서치**
안전/주의/위험을 색상만으로 구분하면 안 된다는 것을 확인하기 위해 색각 이상 관련 UI 가이드를 먼저 받았습니다.
> "적록색각이상 사용자를 고려한 상태 표시 UI 가이드를 만들어줘. 색상만 쓰면 안 되는 이유와, 색상 외에 함께 써야 할 보조 표시 방법(아이콘, 텍스트, 패턴)을 표로 정리해줘."

AI가 제안한 방법 중 "패턴(빗금) 추가"는 좁은 배지 안에서 시각적으로 지저분해져 제외하고, 아이콘+한글 라벨 병기 방식만 채택해 `Badge` 컴포넌트에 반영했습니다.

**③ 개발 단계 — 컴포넌트 초안 생성**
카메라 뷰파인더처럼 브라우저 API가 얽힌 컴포넌트는 동작을 자연어로 설명해 초안을 먼저 받았습니다.
> "React로 후면 카메라를 getUserMedia로 띄우고, 셔터 버튼을 누르면 현재 영상 프레임을 canvas로 캡처해서 base64 이미지로 저장하는 컴포넌트를 짜줘. 컴포넌트가 언마운트될 때 스트림 트랙은 반드시 정지시켜줘."

AI가 만든 초기 코드는 카메라 권한이 거부됐을 때 화면이 그대로 멈춰버리는 문제가 있어, `try/catch`로 감싸고 권한 거부 시에도 앨범 업로드로 이어지도록 분기 처리를 직접 추가했습니다.

**④ 카피라이팅 — 화면 문구 다듬기**
위험 등급 안내 문구는 사용자가 놀라지 않으면서도 경각심은 확실히 느끼도록 여러 톤을 받아본 뒤 골랐습니다.
> "전자레인지에 절대 넣으면 안 되는 재질(스테인리스, 알루미늄) 스캔 결과에 뜨는 경고 문구를 2가지 톤으로 제안해줘. 하나는 단호한 톤, 하나는 이유를 설명하는 톤으로."

AI가 제안한 "위험! 절대 사용 금지"류의 단호한 문구는 근거 없이 겁만 준다는 느낌이 강해 제외하고, "전자파를 반사해 불꽃을 일으킨다"처럼 이유를 짧게 덧붙이는 설명형 문구로 최종 확정했습니다.

**⑤ 트러블슈팅 — 원인 진단**
버그 증상을 설명해 원인 후보를 먼저 받아본 뒤, 실제 원인을 좁혀나갔습니다. (아래 트러블슈팅 표 참고)

> 상세 기획 프롬프트(등급 분류 기준, 재질별 안전 수칙 초안 등)는 노션 기획서 4번 섹션에서 더 볼 수 있습니다.

## 🩹 트러블슈팅

| 이슈 | 원인 | 해결 |
|---|---|---|
| 스캔 후 저장했는데 홈/마이페이지 통계가 바로 갱신되지 않음 | `localStorage` 값만 바뀌고 다른 컴포넌트는 이를 감지하지 못함 | `wavescan_data_change` 커스텀 이벤트를 dispatch하고, `useData` 훅에서 이를 구독해 상태를 다시 읽어오도록 처리 |
| 모바일 사파리에서 카메라 화면이 검은 화면으로 멈춤 | `<video>` 태그에 `autoplay`만 있고 `playsInline`, `muted` 속성이 빠져 자동재생이 차단됨 | `playsInline`, `muted` 속성 추가 및 `play()` 실패 시 조용히 무시하도록 예외 처리 |
| 위험 등급 용기도 배지 색만으로는 안전 등급과 헷갈린다는 피드백 | 배지가 배경색 차이로만 구분되어 있었음 | 배지에 ✅/⚠️/🚫 아이콘과 "안전/주의/위험" 한글 라벨을 항상 함께 표시하도록 변경 |
